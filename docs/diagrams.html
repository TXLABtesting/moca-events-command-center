01

Architecture Diagram

مخطط معمارية النظام

Three tiers behind one HTTPS origin: the React single-page app in the browser, the Express + tRPC API, and MySQL. Sign-in is local accounts today and Microsoft SSO (OIDC against Azure AD) when IT switches AUTH_MODE.

  • One origin serves the built SPA and the API — no CORS surface in production.
  • state router is the only writer of ui_state; every mutation passes the per-key role matrix and lands a row in audit_log.
  • Switching to SSO is configuration (AUTH_MODE=oidc + Azure AD app registration), not code.
02

Data Flow Diagram

مخطط تدفق البيانات

What happens to one edit — say an admin adds a team member. The write is cached locally, debounced, then crosses to the server where the role gate and validators decide before anything touches the database. Reads reverse the path at sign-in.

  • The role gate is per key: e.g. wef_tledits (timeline) accepts admin only; tracker keys accept admin, stream lead and team; wef_approvals accepts admin and H.E.
  • Every accepted write lands an audit_log row — actor, key, payload size, timestamp.
  • The Team Guide popup reads the same hydrated React state, so it always matches what the dashboard shows.
03

Process Diagram

مخطط سير العمليات — ترشيح الأعضاء واعتمادهم

The platform's flagship approval workflow: a team nominates a member, the admin decides, and an approval fans the change out to every session. The same lane pattern governs task edits and timeline changes (admin-only lanes there).

  • Nothing reaches the shared roster without either an admin action or an admin approval — the queue is the only path for non-admin edits.
  • Rejections leave no roster change but remain visible in the audit trail.
  • The green fan-out is the read path from diagram 02: every session hydrates the approved roster at sign-in, and open Team Guides refresh live.
